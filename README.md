# AI Services Explained

GitHub repository: https://github.com/yves-schillings/ai-services-explained

Commented Python examples for the Secloudis article *AI Services Explained*.
All code in this repository is written by **Yves Schillings**.

Everything uses **fictional data** generated by the code. No real organisation,
case or person appears, and no example downloads model weights or calls a hosted model.

All examples are in `examples/`:

- **Training examples (01, 02 and 13 to 17).** Each one trains a model, evaluates it
  on separate data and writes its measured results to `results/`. The article and its
  slides show exact excerpts of these files and link to the lines they quote.
- **Model serving (18).** A FastAPI service that loads the trained document-triage
  pipeline only after checking its checksum.
- **Service examples (03 to 12).** Short inference, retrieval, agent, OCR and speech
  examples. Several need a local model server or engine. Their tests check the
  application controls with mocked model calls. They do not measure model quality.

`fictional_data.py` and `page_images.py` generate the fictional documents and page
images used by the training examples.

## Run the training examples

Python 3.12, CPU only. Install the requirements, then run from the repository root:

```powershell
python -m pip install -r requirements.txt
python examples/01_machine_learning.py        # classification, leakage, artifact, monitoring
python examples/13_regression.py              # regression, underfitting and overfitting
python examples/14_clustering.py              # clustering with dimensionality reduction
python examples/15_anomaly_detection.py       # anomaly detection
python examples/16_time_series_forecast.py    # time series with a temporal split
python examples/02_deep_learning.py           # MLP and CNN training loop, adaptation
python examples/17_autoencoder.py             # autoencoder for unusual pages
python -m pytest tests -q
```

Serve the trained pipeline after running example 01:

```powershell
python examples/18_model_serving.py           # serves on 127.0.0.1:8800
```

## Measured results

Executed on a laptop CPU with Python 3.12, scikit-learn 1.8 and PyTorch 2.12 (CPU build).
Exact values and charts are in `results/`. They show mechanisms on fictional data,
not the quality of any production system.

| Example | What it shows | Measured result |
| --- | --- | --- |
| 01 document triage | TF-IDF + Logistic Regression, split by case | 200 cases: test macro-F1 0.848, below the 0.85 gate. 400 cases: 0.895, passes |
| 01 leakage check | Same data, random split instead of split by case | 0.930 and 0.942: the leak inflates the score |
| 01 monitoring | A new batch with unseen words | Review share rises from 22 % to 56 %: investigate |
| 13 regression | Gradient boosting regression of processing time | Test MAE 5.4 minutes, R² 0.935. Depth 1 underfits, depth 10 overfits |
| 14 clustering | TF-IDF, SVD to 20 dimensions, K-means | Silhouette picks k = 3. The rare type is absorbed: an analyst must check |
| 15 anomaly detection | Isolation Forest | All 21 injected records in the top 25 of the review list |
| 16 time-series forecast | Temporal split | Test MAE 30.4 documents per day against 37.2 for last week's value |
| 02 page layout | MLP and CNN trained with early stopping | CNN 0.990 on clean and 0.935 on degraded test pages |
| 02 adaptation | 8 labelled pages per type | Fine-tuning 0.95, scratch 0.94, frozen features 0.85 |
| 17 autoencoder | Reconstruction error | 100 % of unusual pages flagged, 6 % of usual pages |

## What each training example teaches

- **01**: the full lifecycle. Need and acceptance criterion, data sample, split by
  case, hyperparameters chosen on validation, one final test, leakage, saved
  pipeline with a manifest, inference from the artifact, and monitoring after release.
- **02**: forward pass, loss, backpropagation, optimiser step, batch, epoch,
  learning rate, early stopping, and feature extraction versus fine-tuning.
- **13**: regression and the difference between underfitting and overfitting.
- **14**: unsupervised grouping and dimensionality reduction with TruncatedSVD.
- **15**: unsupervised anomaly scores. An anomaly is never evidence of wrongdoing.
- **16**: why a time series needs a temporal split, and a leaky centred average.
- **17**: learning a representation without labels.
- **18**: serving the saved artifact, with a checksum check before loading.

## Service examples

03 local language inference, 04 controlled draft generation, 05 permitted semantic
retrieval and generation, 06 bounded tool use, 07 OCR, 08 transcription,
09 multimodal interpretation, 10 embeddings, 11 translation and 12 elementary redaction.
Examples 03 to 06 and 09 to 11 need a model already installed in a local Ollama
server. The HTTP client is fixed to 127.0.0.1 and disables inherited proxies. This
does not establish the security or offline configuration of that server.
Speech needs faster-whisper with local model files. OCR needs the Tesseract
executable and its language data on PATH.

## Verification

`python -m pytest tests -q` runs 28 deterministic tests:

- `tests/test_training.py` checks the split by case, the vectoriser fitted on
  training data only, the review threshold, forecast features that use only the past,
  the service refusing a modified artifact, and frozen layers that do not change.
- `tests/test_examples.py` checks access filtering, schema refusal, agent tool
  permissions and bounded execution of the service examples, with mocked model or OCR calls.

## Limits

The data is synthetic and small. The scores show how training and evaluation work.
They are not evidence of quality on real documents, recordings or languages.
These are educational applications, not a complete authentication service or
production deployment bundle. Check upstream package and model licences before any deployment.
